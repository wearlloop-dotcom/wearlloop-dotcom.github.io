# ออดิท: Workflow การส่ง LINE Flex Message หาลูกค้าหลังเกิด action

วันที่ออดิท: 2026-07-02 · ขอบเขต: รีโป `wearlloop-dotcom.github.io` (frontend ทั้งหมด)
เทมเพลต Flex Message พร้อมใช้: [`docs/line-flex-templates.md`](./line-flex-templates.md)

## ข้อสรุปหลัก (TL;DR)

1. **Frontend ในรีโปนี้ไม่มีกลไกส่ง LINE message หาลูกค้าเลย ยกเว้นจุดเดียว** — การ์ด Flex ชวนเข้ากลุ่มใน `family.html` (ลูกค้ากดแชร์เอง ผ่าน `liff.shareTargetPicker`)
2. **การส่ง push หลัง action ทั้งหมดอยู่ฝั่ง backend (Supabase)** ซึ่งไม่อยู่ในรีโปนี้ — จาก frontend เห็นหลักฐานว่า backend ส่งจริงแค่ **2 workflow**: แจ้งชุด wishlist เข้า (`notify_customer_wishlist`) และชุดใหม่ขึ้นร้าน (`mark_garment_ready` → `new_arrival`)
3. **มี 7 จุดที่ UI "สัญญา" กับลูกค้าว่าจะแจ้งทาง LINE แต่ไม่พบโค้ดที่ส่ง** — เสี่ยงผิดคำสัญญากับลูกค้า
4. **`webhooks.js` เป็นโค้ดตายทั้งไฟล์** — นิยาม 4 webhook (order-confirmed, new-arrivals, return-reminder, request-review) แต่ไม่มีที่ไหนเรียกใช้ และ `N8N_BASE_URL` ใน `config.js` ยังว่าง

## 4.1 ออดิทเพิ่มเติม: สเตตัสขนส่ง · เตือนส่งคืน · เลขพัสดุขากลับ

| คำถาม | ผลออดิท | สิ่งที่ทำ |
|---|---|---|
| มีสเตตัสขนส่งไหม | มีบางส่วน — การ์ดใน "ออเดอร์ของฉัน" โชว์ขนส่ง+เลขพัสดุ**ขาไป**เป็นลิงก์กดตามได้ (`app.js` `COURIER_TRACK` รองรับ Flash/Kerry/J&T/ไปรษณีย์ไทย/Ninja) แต่สถานะลูกค้ามีแค่ `out` = "จัดส่ง/กำลังใช้" ก้อนเดียว ไม่แยก "กำลังส่ง/ถึงแล้ว" (ฝั่งออปส์ `garment_timeline` มี event ละเอียดกว่า: shipped, in_transit, delivered, return_shipped, returned) และ**ไม่มี LINE Flex แจ้งตอนส่งของ** | เทมเพลต #4 `order_shipped` (ปุ่ม "ติดตามพัสดุ" + "วิธีคืนชุด") |
| มีการแจ้งเตือนให้ส่งของกลับไหม | **ไม่มีที่ทำงานจริง** — มีแค่ stub `returnReminder` ใน `webhooks.js:20` ซึ่งไม่ถูกเรียกและ n8n ยังไม่ต่อ | เทมเพลต #5 `return_reminder` อัปเดตให้ปุ่มหลักเป็น **"กรอกเลขพัสดุส่งคืน"** + ปุ่มรอง "ต่อวันเช่า", "วิธีคืนชุด" |
| มีช่องกรอกเลขพัสดุส่งคืน (เลข ปณ.) ไหม | **ไม่มีเลยทั้งระบบ** — ลูกค้าไม่มีที่กรอกเลขพัสดุขากลับ ทั้งที่ timeline ฝั่งร้านมี event `return_shipped` "ลูกค้าส่งคืน" รออยู่แล้ว | **เพิ่มให้แล้วในแอป:** ปุ่ม "แจ้งส่งคืน · กรอกเลขพัสดุ" บนการ์ดออเดอร์สถานะ `out` (`app.js`) — กรอกเลขพัสดุ+เลือกขนส่ง (เดา EMS อัตโนมัติจากรูปแบบ XX#########TH) แล้วบันทึกผ่าน `API.submitReturnTracking` → RPC `return_tracking_submit` และโชว์แถว "ส่งคืน" พร้อมลิงก์ตามพัสดุเมื่อกรอกแล้ว + เทมเพลต 5.1 `return_tracking_received` ยืนยันกลับทาง LINE |

> ฝั่ง backend ต้องสร้าง RPC `return_tracking_submit(p_rental, p_courier, p_tracking_no)` และให้ `my_rentals` คืนฟิลด์ `return_courier`, `return_tracking_no` เพิ่ม — รายละเอียดใน `line-flex-templates.md` หัวข้อ "หมายเหตุการต่อระบบ"

## 4.2 ออดิทความครบถ้วนจากมุมมองลูกค้า (ทั้ง journey)

ไล่ตาม customer journey แล้วเทียบว่ามีเทมเพลต Flex รองรับครบไหม — **หลังเติมภาค 2 แล้ว ครอบคลุมทุกจุดที่ลูกค้าคาดหวังการแจ้งเตือน:**

| ช่วง journey | เหตุการณ์ที่ลูกค้าคาดหวังข้อความ | เทมเพลต |
|---|---|---|
| สมัคร/เริ่มใช้ | KYC ผ่าน → เช่าได้แล้ว | #14 `welcome_kyc_approved` |
| เลือกชุด | ชุดใหม่ตรงสไตล์ · ชุดที่ขอเข้าคลัง · คิวว่าง · ตะกร้าค้าง | #20, #8, #9, #27 |
| จอง | ยืนยันการจอง · สลับชุดสำรอง | #1, #17 `spare_swap_notice` |
| จ่าย | ใกล้หมดเวลาถือคิว · สลิปผ่าน · สลิปไม่ผ่าน · เตือนหารกลุ่ม | #15, #2, #3, #12 |
| รอรับชุด | จัดส่งแล้ว+เลขพัสดุ | #4 |
| ใช้/เปลี่ยนแผน | ยกเลิก/เลื่อน/ต่อเวลา สำเร็จ | #16 `booking_changed` |
| คืนชุด | เตือนคืน (มีปุ่มกรอกเลขพัสดุ) · รับเลขพัสดุแล้ว · เลยกำหนด+ค่าปรับ | #5, #5.1, #18 `overdue_notice` |
| ปิดจบ | QC ผ่าน+ขอรีวิว · มีค่าดูแลเพิ่ม · **เงินคืนโอนแล้วจริง** · ผลซ่อม | #6, #7, #19 `deposit_refunded`, #11 |
| คอมมูนิตี้/กลุ่ม | ลุคขึ้นฟีด · เพื่อนรับคำเชิญ · การ์ดชวน (แชร์เอง) | #10, #26, family.html |
| กลับมาใหม่ (lifecycle) | เครดิตใกล้หมด · วันเกิดเช่าฟรี · เครดิตชวนเพื่อน · ผลวิเคราะห์สี · นัดสไตลิสต์ | #21, #22, #23, #24, #25 |
| สัญญา (พาร์ทเนอร์) | สำเนาสัญญา | #13 |

จุดที่**จงใจไม่ทำ** Flex (กันสแปม): กดไลก์/คอมเมนต์/โหวต, บันทึกโปรไฟล์, งานภายในคลัง — เหมาะกับ inbox ในแอปมากกว่า push
แคมเปญการตลาดที่เหลือ (`reengagement`, `winback`, `event_suggest`, `charity_update`) ใช้โครง #20/#27 เปลี่ยนข้อความได้ ไม่ต้องมีใบแยก

**หลักที่ใช้เช็ค "ครบ" ในมุมลูกค้า:** ทุกครั้งที่ (ก) เงินขยับ (ข) สถานะของที่เช่าเปลี่ยน (ค) ลูกค้าต้องทำอะไรต่อ — ต้องมีข้อความบอก พร้อมปุ่มพาไปทำสิ่งนั้นได้ในแตะเดียว ตอนนี้ครบทั้ง 3 เงื่อนไขแล้วค่ะ

## 5. สิ่งที่แก้ในรีโปนี้แล้ว

- `family.html` — เพิ่มปุ่มรอง "ดูชุดให้เช่าก่อน" ในการ์ด Flex ชวนเข้ากลุ่ม (ลิงก์เปิดหน้าร้านผ่าน LIFF)
- `app.js` — การ์ด "ออเดอร์ของฉัน": ปุ่ม "แจ้งส่งคืน · กรอกเลขพัสดุ" (สถานะ out) + แถว "ส่งคืน" พร้อมลิงก์ตามพัสดุขากลับ
- `api.js` — เพิ่ม `submitReturnTracking()` เรียก me-rpc `return_tracking_submit`
- `docs/line-flex-templates.md` — เทมเพลต Flex 28 ใบพร้อมปุ่ม ครอบคลุมทั้ง customer journey (ภาค 1: หลัง action หลัก 14 ใบ · ภาค 2: เติมครบวงจร 14 ใบ) copy ไปใช้ฝั่ง backend ได้ทันที
- `docs/line-flex-audit.md` — รายงานฉบับนี้

## 6. ข้อเสนอถัดไป (ฝั่ง backend — อยู่นอกรีโปนี้)

1. ปิด gap ข้อ 2 (คำสัญญาใน UI) ก่อน — โดยเฉพาะ **แจ้งผลสลิป** และ **คิวว่าง** เพราะลูกค้ารออยู่จริง
2. เพิ่ม push จุดที่เก็บเงินลูกค้า (**QC หักมัดจำ**) — โปร่งใสเรื่องเงินสำคัญสุด ลดดราม่า/ดิสพิวต์
3. ยิงจาก Supabase (DB trigger ผ่าน pg_net หรือ Edge Function หลัง RPC สำเร็จ) — อย่ายิงจาก frontend เพราะผู้ใช้ปิดหน้าก่อนได้
4. ตัดสินใจเรื่อง `webhooks.js`: ถ้าจะใช้ n8n ให้ใส่ `N8N_BASE_URL` และเรียก stub จาก handler จริง; ถ้าไม่ใช้ ให้ลบไฟล์ทิ้งกันสับสน
5. ทุก push ควร insert ลง notification inbox ในแอปคู่กัน (kinds มีรออยู่แล้วใน `app.js:3676-3698`)
